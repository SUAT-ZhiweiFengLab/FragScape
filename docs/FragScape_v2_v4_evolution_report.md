## 2. FragScape 2.0 原始架构

### 2.1 数据集构建思路

分两个阶段：

**阶段 1 — 合并短肽来源** (`merge_all_sources.py`)
将 6 个离散数据源合并为统一的 `dataset_v2_merged.csv`：

| 来源 | 数据量 | 说明 |
|------|--------|------|
| v1.0 核心集 (`dataset.csv`) | 13,312 | 含 CD-HIT split，作为锚定核心 |
| m10_run/dataset.csv | 18,392 | M10 (MMP) 家族独立实验 |
| final_run/dataset.csv | 11,909 | MEROPS 全量提取 |
| hard_neg_data/dataset_hardneg.csv | 25,970 | M10+M12 同底物硬负样本 |
| v3_data/dataset_v3_dedup.csv | 82,794 | 8-mer 去重数据集 |
| m10_collagen_peptides.json | 9,196 | M10 胶原酶肽 |

**最终产出**：106,922 条（53,461 正 + 53,461 负），全部为 2-9 肽。

**阶段 2 — 构建长肽** (`build_long_peptide_dataset.py`)
- 使用 5 条胶原底物（驴 COL1A1/1A2、human COL1A1/1A2）
- 将 v2_merged 中的 53,461 条短肽正样本定位到这些底物上，标记为"切割热点"
- 在底物上滑动 10-20 窗口（stride=1）：
  - 窗口与切割热点重叠 ≥1 残基 → **正样本**
  - 窗口完全不在切割扩展区 → **负样本**

### 2.2 正负样本来源（对比 v1.0）

| 维度 | v1.0 短肽 (2-9) | v2.0 长肽 (10-20) |
|------|-----------------|-------------------|
| **正样本** | MEROPS M10/M12/CLE 实验验证切割位点，8-mer 窗口 | 5 条底物上与切割热点重叠的滑动窗口（推断性） |
| **负样本** | 同一底物远离切割位点 ≥10 残基的区域（硬负） | 底物非覆盖区 + **胶原频率随机生成序列** |
| **划分** | CD-HIT 50% 前体蛋白聚类防泄漏 | 序列 MD5 hash 确定性 8:1:1 |

### 2.3 模型构建路径

```
Frozen ESM-2 (esm2_t12_35M_UR50D, 35M params, 480-dim)
  → Learnable Positional Encoding (1, max_len, 480)
  → 2-layer TransformerEncoder (4 heads, ffn=1024, Pre-norm, GELU)
  → Gated Fusion: F_fused = g·F_peptide + (1-g)·F_protein
  → Residual Conv1D ×3 (480→128→64→32, k=3)
  → Hybrid Pooling (0.5·Avg + 0.5·LSE)
  → Dropout(0.3) → Linear(32, 1) → Sigmoid
```

**训练配置**：AdamW(lr=5e-4) + CosineAnnealing + FocalLoss(γ=2, α=0.75), 25 epochs, batch=64

### 2.4 v2.0 与 v1.0 的核心区别

| | v1.0 | v2.0 |
|---|------|------|
| **模型架构** | 完全相同 | **完全相同** |
| 位置编码 | (1, 9, 480) 固定 | (1, max_len, 480)，通过 `--max-len` 参数可配 |
| 支持肽长 | 2-9 | 2-20（默认 12） |
| 训练数据 | 13,312 条 | 186K+ 条（短+长混合） |
| 代码文件 | `fragscape.py`/`train.py` | `fragscape.py`/`train_v2.py` |

**结论**：v2.0 = v1.0 架构零变化，仅 `max_len` 参数化 + 配套长肽数据集。

## 4. v2.0 Enhanced（扩大数据但加剧缺陷）

### 4.1 改进措施

创建 `build_long_peptide_dataset_enhanced.py`：
- **25 条胶原底物**（驴/牛/马/猪/人，COL1A1 到 COL16A1，34,076 残基）
- 同时整合 MEROPS 17,907 条切割位点（三字母码→单字母码转换）
- 外部数据源（BIOPEP、derived_peptides、l1_training_data）

### 4.2 产出数据

| 文件 | 规模 | 说明 |
|------|------|------|
| `dataset_long_enhanced_10_12.csv` | **79,908** | 39,954 正 + 39,954 负 |
| `dataset_long_enhanced_10_15.csv` | 167,840 | 83,920 正 + 83,920 负 |
| `dataset_long_enhanced_10_20.csv` | 325,618 | 162,809 正 + 162,809 负 |

### 4.3 训练结果

- **训练样本**：186,830 条（v2_merged 106,922 + enhanced_10_12 79,908）
- **testAUC**：0.9419
- **F1@0.7**：0.8232

### 4.4 对 GFPGTPGLPGVK 的预测：**0.9890** 🚨

**这引发了质疑**：从 0.55 跳到 0.99，差异太大。

### 4.5 根因排查

#### 问题 1：GFPGTPGLPGVK 在训练集中！

| 位置 | Split | Label |
|------|-------|-------|
| `dataset_long_enhanced_10_12.csv` | train | 1 |

该序列在 COL2A1 底物上滑动时，与切割热点重叠，被标记为正样本并被 hash 分配到了 train 集。

#### 问题 2：子序列泄漏

GFPGTPGLPGVK 的所有 9-mer 子序列大量出现在 train 中：
- `GFPGTPGLP` → 匹配 18 处 train 序列
- `FPGTPGLPG` → 匹配 22 处 train 序列
- `PGTPGLPGV` → 匹配 7 处 train 序列
- `GTPGLPGVK` → 匹配 6 处 train 序列

v2_merged 中还有 44 个子序列（如 `GTPGLP`、`PGTPG`、`FPGTPG` 等）散布在 train 中。

**胶原 Gly-X-Y 重复序列特性**：相邻窗口天然高度重叠，即使排除完全匹配的 12 肽，其 6-11 mer 子序列仍然遍布训练集。

#### 问题 3：99.6% 负样本是随机生成的！🌟 核心缺陷

| 负样本类型 | 数量 | 占比 |
|-----------|------|------|
| substrate_uncovered（真硬负） | **115** | 0.36% |
| random_synthetic（随机生成） | **31,801** | **99.64%** |

**破坏性影响**：
- 正样本来自真实胶原底物，含 GP/PG 重复特征
- 负样本是按氨基酸频率随机生成的序列，没有胶原特征
- **模型实际学的不是"切割 vs 非切割"，而是"胶原序列 vs 随机序列"**
- GFPGTPGLPGVK 是纯正的胶原序列 → 当然得高分
- 这解释了为什么 testAUC 高达 0.94：区分胶原/非胶原太容易了

### 4.6 清洗尝试

- 剔除 GFPGTPGLPGVK + 高相似度（≥10/12 match）序列 + v2_merged 子序列 → 移到 test
- 重新训练 → prob 仍为 **0.9890**（问题不是同序列泄漏，而是数据设计缺陷）

## 5. v3.0 全面升级（矫枉过正）

### 5.1 改进措施

创建 `build_long_peptide_v3.py`：

1. **MEROPS 精确集成**（修复三字母码→单字母转换）：
   - 17,907 条 M10/M12/CLE 切割记录
   - 176 次切割位点成功定位到 25 条底物上

2. **COL2A1 完全隔离为 test 集**：
   - human_COL2A1 → test
   - 其他人类胶原 → val
   - 动物胶原 → train

3. **100% 同底物硬负**：
   - 0 条随机生成负样本
   - 全部负样本来自底物非切割区域

4. **v2_merged 清洗**：
   - 2,896 条出现在 COL2A1 中的序列 → 移入 test

### 5.2 产出数据

| 指标 | 值 |
|------|-----|
| 文件 | `dataset_v3_10_12.csv` |
| 总样本 | 18,491 条 |
| train | 4,108 (9个底物) |
| val | 11,748 (15个底物) |
| test | **2,635 (仅1个底物 COL2A1)** |

### 5.3 问题

**test 集严重失衡**：
- test 只有 1 个底物 COL2A1
- 2,426 正 vs 209 负（比例 11.6:1）
- AUC 评估基本无意义

**train 数据太少**：
- 仅 4,108 条，远不够训练 10-12 肽的切割模式
- MEROPS 切割核心覆盖面不足（仅 176 次成功定位）

### 5.4 训练结果

- **testAUC**：0.7964（从 0.94 暴跌，因为现在 test 是真正的 holdout）
- **GFPGTPGLPGVK**：**0.4297**（被判定为低概率非切割）

## 6. v4.0 平衡版（最终方案）

### 6.1 设计思路

目标：足够数据训练 + 多个异构底物测试 + 合理评估

#### Split 策略：底物类型交叉

| Split | 底物 | 数量 |
|-------|------|------|
| **train** | 动物胶原 + 主要人类胶原（COL1A1/1A2/3A1/4A1/4A2） | 16 个 |
| **val** | COL6A1/6A2/5A2/COL5A1/COL7A1 | 5 个 |
| **test** | COL2A1 + COL8A1 + COL12A1 + COL16A1 | 4 个 |

#### v2_merged 温和清洗

- 仅将 COL2A1 中长度 ≥7 的子序列移到 test（1,086 条）
- 短肽（2-6）保留在 train 中，避免过度削减训练数据

### 6.2 产出数据

| 文件 | 规模 |
|------|------|
| `dataset_v4_10_12.csv` | **20,590** 条（train 10,026 / val 2,424 / test 8,140） |
| `dataset_v2_merged_v4.csv` | 106,922 条（1,086 条 COLA21 长片段→test） |

### 6.3 训练结果

- **总训练样本**：127,512 条
- **testAUC**：0.7364（best valAUC=0.7960）
- **F1@0.7**：0.4687

AUC 低于 v2.0 的 0.94，但这是**真实的泛化性能**——test 包含 4 个模型从未见过的底物类型。

### 6.4 GFPGTPGLPGVK：**0.4495**

在 COL2A1 上下文中评估（v4 模型）：

GARGFPGTPGLP:  0.5206

GLDGAKGEAGAP:  0.3379

GFPGTPGLPGVK 在 COL2A1 所有 12-mer 中处于中等偏低位置，4 个序列高于它，3 个低于它。

## 7. 四版模型预测对比

| 版本 | 模型 | GFPGTPGLPGVK | testAUC | 可信度 | 主要问题 |
|------|------|-------------|---------|--------|----------|
| v1.0 | 仅 2-9 短肽训练 | **0.5509** | 0.9566 | ★★★ | 未见长肽，保守外推 |
| v2.0 enhanced | 含 10-12 长肽（泄漏） | **0.9890** | 0.9419 | ★ **假象** | train 有子序列 + 99.6% 随机负样本 |
| v3.0 | COL2A1 完全隔离 | **0.4297** | 0.7964 | ★★ | 仅 1 底物 test + 数据太少 |
| **v4.0** | **交叉 split, 平衡** | **0.4495** | 0.7364 | **★★★★** | **当前最佳估计** |

### 结论

GFPGTPGLPGVK 在 FragScape 框架下的切割概率约为 **0.45-0.55**，始终低于 0.7 决策阈值，**不被视为高置信切割产物**。

v2.0 enhanced 的 0.989 是数据设计缺陷导致的假高分，其根本原因是 **99.6% 的负样本为随机生成序列**，使模型退化为"胶原序列分类器"。

## 8. 核心发现与教训

### 8.1 虚拟负样本问题

| | 若负样本是随机生成 | 若负样本是同底物硬负 |
|---|---|---|
| 模型目标 | 区分"天然序列 vs 随机序列" | 区分"切割位点 vs 非切割位点" |
| 胶原肽预测 | 全部高分（因为来自底物） | 取决于局部切割信号 |
| testAUC | 虚高 0.94 | 反映真实泛化 |
| 对 GFPGTPGLPGVK | 0.99（假） | 0.45（真） |

### 8.2 胶原序列的固有问题

胶原蛋白的 Gly-X-Y 重复模式导致：
1. 相邻滑动窗口大量重叠 → 子序列泄漏无法通过简单去重解决
2. 同源底物间的 ESM-2 embedding 高度相似 → 必须 CD-HIT 级别划分
3. 仅靠序列相似度剔除是不够的，需要底物级别的 split

### 8.3 正确评估长肽切割预测的前提

1. **负样本必须来自真实底物非切割区**（不是随机生成的）
2. **split 必须按底物级别而非序列级别**（同一底物的窗口不能分散在 train/val/test）
3. **test 需要多个异构底物**（至少 3-4 个，覆盖不同胶原类型）
4. **不能期望 testAUC 和短肽 v1.0 一样高**（长肽预测本质上更难）
